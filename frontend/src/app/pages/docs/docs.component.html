What is Alias AI?

0.00% Leakage Guarantee

Alias AI is an open-source, sovereign, zero-knowledge privacy airgap gateway designed for AI coding agents, enterprise developers, and automated data pipelines. It sits locally on your workstation, intercepting outbound LLM traffic over the standard OpenAI protocol (http://127.0.0.1:8080/v1).

💡
Zero Refactoring Required: Alias AI speaks standard OpenAI wire protocol. Whether you use Cursor IDE, LangChain, Claude Code, Python, or shell scripts, you only need to change your base URL to http://127.0.0.1:8080/v1.

The Core Problem

Modern AI workflows require sending source code, stack traces, and customer inputs to third-party cloud LLMs. In doing so, developers inadvertently leak:

  • Automotive VINs: ISO 3779 vehicle identification numbers exposing customer vehicles and fleet telemetry.
  • European Banking Data: German SEPA IBANs and account routing info subject to GDPR Art. 25 strict liabilities.
  • Production Credentials: AWS access keys, GitHub personal tokens, NVIDIA/OpenAI API keys, and PostgreSQL connection strings.
  • Internal Network Topology: Private IPv4 subnets (10.0.0.0/8) and corporate hostnames (*.internal).

When these secrets touch cloud servers, they are logged in plain text, stored across multi-tenant GPU clusters, and vulnerable to sub-processor data leaks.

The Alias AI Solution

Alias AI intercepts every outgoing prompt before it ever initiates a TLS handshake with cloud servers. It extracts confidential data into an ephemeral local RAM vault, substitutes each value with a semantically typed alias (e.g. <ALIAS_VIN_1>, <ALIAS_IBAN_1>), and mathematically validates that zero private entropy exists on the outbound wire.

Security Invariants

  1. Zero Disk Persistence: Secrets stored in the Ephemeral Vault are retained strictly in process.memory. When the session terminates or proxy restarts, the vault is completely destroyed.
  2. Deterministic Replacement: Secrets are replaced before any HTTP socket connection to the upstream LLM is initiated.
  3. Pass-Through Streaming by Default: Streamed tokens are passed directly to the caller with aliases intact to prevent token buffering latency. Client-side re-hydration is available via the -r flag.

Zero-Leakage Guarantee (E_leak = 0.00%)

Alias AI mathematically asserts that not a single byte of confidential information reaches the cloud.

Empirical Entropy Leakage Formula
E_leak = ( Σ I(v_i ∈ P_egress) / N ) × 100% ≡ 0.00%

Where V = {v_1, v_2, ..., v_N} is the set of all extracted raw secret values stored in the Ephemeral Vault, and P_egress is the string payload prepared for network transmission.

Egress Firewall Invariant Enforcement

If any raw secret v_i is detected in the outbound payload (E_leak > 0), the proxy instantly:

  • Terminates the TCP connection before sending any HTTP headers.
  • Emits an EntropyLeakageViolation alert to the audit logger.
  • Purges the active session vault to prevent residual memory leakage.

Ephemeral In-Memory RAM Vault

Bidirectional, high-performance mappings stored exclusively in volatile memory.

The engine maintains two hash maps for O(1) bi-directional lookups:

  • vault: Map<rawSecret, aliasPlaceholder> — Maps secret to token for fast outbound substitution.
  • reverseVault: Map<aliasPlaceholder, rawSecret> — Maps token back to raw value for local re-hydration.
  • counterByType: Map<entityType, number> — Maintains deterministic indexing per entity category (e.g. <ALIAS_VIN_1>, <ALIAS_VIN_2>).
⚠️
Persistence Safety: The vault is never written to disk, cache files, temporary logs, or browser localStorage. Closing the process wipes all secrets permanently.

Sliding-Window Streaming Re-hydrator

How Alias AI solves the Server-Sent Events (SSE) token boundary splitting problem.

The Token-Split Challenge

When cloud models like NVIDIA Nemotron or GPT-4 stream output in tiny chunks (1-3 characters), an alias like <ALIAS_VIN_1> often arrives fragmented across multiple packets:

Chunk 1 "The VIN is <ALIAS_"
Chunk 2 "VEHICLE_"
Chunk 3 "VIN_1> confirmed."

A naive token-by-token replacement fails because neither Chunk 1 nor Chunk 2 contains the complete closing delimiter (>).

The State Machine Algorithm

Alias AI implements a stateful sliding-window streaming buffer:

  1. Buffer Carry-Over: Retain partial trailing alias prefixes matching /<ALIAS_[A-Z0-9_]*$/ in an internal sliding window.
  2. Immediate Safe Flush: Confirmed safe text preceding the partial tag is flushed to the caller immediately, preserving full model streaming velocity.
  3. Atomic Tag Resolution: When the closing delimiter (>) is received, the complete token is looked up in the reverseVault and replaced atomically.

Troubleshooting & Diagnostics

Solutions to common configuration, network, and runtime issues.

Port 8080 is already in use by another process

Alias AI automatically attempts to bind to 8081 if 8080 is busy. You can also explicitly specify any port: 

alias-ai start --port 9090

Where do I put my real cloud API key?

Store your real NVIDIA or OpenAI API key in a .env file in your current working directory or in ~/.alias-ai/.env: 

OPENAI_API_KEY=nvapi-your-real-nvidia-key
UPSTREAM_URL=https://integrate.api.nvidia.com/v1

Your client tools only ever receive or transmit alias-local-token.

Why does my LLM output have <ALIAS_*> tokens?

This is the default privacy-first behavior. By returning placeholders, Alias AI delivers zero-latency streaming. If your application requires real values in the final text on localhost, pass the -r (or --rehydrate) flag: 

alias-ai start --rehydrate

Frequently Asked Questions (FAQ)

Does Alias AI add latency to my LLM calls?

No perceptible latency. The deterministic regex classifier executes in under 0.5 milliseconds, which is negligible compared to the 200ms – 1500ms network roundtrip of cloud LLMs.

Does the cloud model get confused by <ALIAS_*> tokens?

Frontier models (like NVIDIA Nemotron-70B, GPT-4o, and Claude 3.5 Sonnet) understand typed semantic placeholders naturally. Because tokens like <ALIAS_VEHICLE_VIN_1> preserve entity semantics and sentence grammar, model reasoning accuracy remains virtually identical to unmasked text.

Can an attacker recover my secrets from prompt logs in the cloud?

No. Because secrets never leave your local RAM, cloud logs only ever record the opaque <ALIAS_*> tokens. The mathematical leakage score is verified at 0.00%.
